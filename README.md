# agent-hq-kit — штаб и память для ваших ИИ-агентов

Это шаблон рабочего слоя для тех, кто работает с несколькими ИИ-агентами (Claude Code, Codex и другими) и устал объяснять каждому одно и то же. Из шаблона получается ваш личный приватный репозиторий, «штаб». В нём три вещи.

**Единые правила для всех агентов.** Как агент говорит с вами, как доказывает, что сделал, где ему нужно ваше «ок», как ведёт задачу от черновика плана до коммита. Всё это лежит в одном файле `doctrine/AGENTS.md` и подключено к каждому агенту ссылкой. Правило меняется в одном месте, и его сразу видят все.

**Управление работой.** Задачи живут в GitHub Issues штаба: тикет это обещание довести дело до конца и закрыть. Вопросы к вам живут там же с лейблом `needs-owner`, поэтому не теряются в переписке. Есть реестр проектов, короткие записи решений (ADR) и уроки, которые агенты пишут после ваших поправок, чтобы не наступать на те же грабли.

**Память о прошлой работе.** История всех сессий всех агентов выгружается в markdown, и [QMD](https://github.com/tobi/qmd) ищет по ней локально, по словам и по смыслу. Агент может ответить на вопрос «как мы это решали в прошлом месяце» и проверить, не устарел ли ответ.

## Как начать

Установку делает ваш агент, а не вы. Склонируйте этот репозиторий, откройте Claude Code или Codex в его каталоге и скажите:

> Прочитай SETUP.md и помоги мне всё настроить.

Агент сначала посмотрит, что стоит на машине, и задаст несколько вопросов: где будет штаб, каких агентов подключать, какие папки добавить в поиск. Потом он пройдёт шесть фаз, перед каждой скажет, что изменится, и после каждой покажет проверку. Ваше участие сводится к ответам, «ок» и вводу пароля там, где без вас нельзя. Свой приватный штаб агент сделает из клона, а не кнопкой «Use this template»: так обновления шаблона потом вливаются обычным слиянием.

Нужны `git`, Python 3.10+, Node.js 22+ (для QMD), GitHub CLI `gh` и хотя бы один агент. Работает на macOS, Linux и Windows. Проверено на Claude Code и Codex на Linux; для macOS и Windows SETUP описывает штатные механизмы этих систем, но на их железе шаблон ещё не прогонялся. Других агентов SETUP подключает по их документации и проверяет живой цитатой правил.

Все правила и документы написаны по-русски, и агенты будут говорить с вами по-русски. Язык задаётся в доктрине, раздел «Язык».

## Как этим жить

**Начало работы.** Открываете агента в проекте и говорите, что делаем. Агент сам прочитает правила проекта и уроки, посмотрит открытые задачи и одной фразой скажет, где проект и что он берёт.

**Задача побольше.** Агент сначала пишет черновик плана, вы ищете в нём дыры, говорите «ок», и только потом начинается код. Задача заводится тикетом в штабе («добавь в беклог …»), коммиты по ней помечаются её номером.

**Вспомнить прошлое.** «Найди, как мы в прошлый раз настраивали деплой» или `/recall деплой`. Агент найдёт сессию, покажет дату и проверит по git и тикету, что было после.

**Конец работы.** «Закрой сессию». Агент закоммитит своё, оставит в тикете итог и что дальше, запушит и в двух строках скажет, что теперь есть.

**Поправка.** Если агент сделал не так, скажите прямо. Он запишет урок, и следующая сессия его прочитает.

## Что где лежит

| Путь | Что это |
|---|---|
| `SETUP.md` | ранбук установки для агента |
| `doctrine/AGENTS.md` | правила для всех агентов |
| `AGENTS.md` | правила штаба: вход, задачи, выход |
| `registry.md` | реестр ваших проектов |
| `skills/` | `recall` (поиск по памяти), `end-session` (выход из сессии), `backlog` (задачи) |
| `memory/` | выгрузка истории сессий Claude Code и Codex и синхронизация с QMD |
| `lessons/` | уроки после поправок |
| `docs/adr/` | почему штаб устроен так, а не иначе |
| `docs/guides/orca.md` | параллельная работа агентов в [Orca](https://github.com/stablyai/orca): задача, worktree, сессия |
| `tests/` | тесты выгрузки на синтетических сессиях: `python3 -m unittest discover tests` |

## Откуда это

Шаблон выжат из рабочего штаба, в котором один человек ведёт с агентами десятки проектов. В облегчённую версию вошло то, что оказалось полезным, а оркестрация, дашборды и журнал шагов остались за бортом. Почему без журнала, объясняет [ADR-0001](docs/adr/0001-no-step-journal.md).
