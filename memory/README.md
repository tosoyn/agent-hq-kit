# Память: история сессий в QMD

Агенты не помнят прошлых сессий. Здесь лежат детали, которые превращают историю сессий в поисковую память: выгрузчики переводят JSONL-логи агентов в markdown, а QMD индексирует markdown и ищет по нему по словам и по смыслу. Установку по шагам ведёт `SETUP.md` в корне штаба, фаза 4. Здесь описано устройство.

## Как это работает

```
~/.claude/projects/**/*.jsonl      сессии Claude Code
~/.codex/sessions/**/*.jsonl       сессии Codex
        │
        │  cc_history_to_md.py, codex_history_to_md.py
        ▼
~/agent-memory/cc-history/         по одному .md на сессию,
~/agent-memory/codex-history/      YAML-шапка по контракту (contract.py)
        │
        │  qmd update (слова), qmd embed (векторы)
        ▼
индекс QMD  ──  MCP-сервер `qmd mcp`  ──  агенты ищут через скилл recall
```

Всё это запускает одна команда `sync.py`. Её зовут хук конца сессии агента (`--detach --source hook`, в фоне) и планировщик системы раз в час (`--source timer`), чтобы догнать сессии, оборвавшиеся без конца. Источник запуска пишется в лог и в `last-run`, поэтому по логу видно, какой из путей работает.

## Файлы

| Файл | Что делает |
|---|---|
| `contract.py` | Общая шапка выгрузки: откуда сессия, где исходник, можно ли её продолжить, обрезана ли. Новый выгрузчик для другого агента импортирует его. |
| `cc_history_to_md.py` | Выгрузка сессий Claude Code. |
| `codex_history_to_md.py` | Выгрузка сессий Codex CLI. |
| `sync.py` | Выгрузка всех источников, затем `qmd update` и `qmd embed`. Замок держит система, и он снимается сам, если прогон упал. Код возврата 1, если хоть одна сессия не прочиталась или `qmd` не запустился. `--status` показывает, когда и кем был запущен последний прогон и чем он кончился. |

Все файлы используют только стандартную библиотеку Python 3.10+ и работают на macOS, Linux и Windows.

## Что попадает в выгрузку и что нет

В выгрузку идут реплики человека, ответы агента, короткие описания вызовов инструментов, вопросы владельцу с вариантами и его выбор, отметки о прерывании. Не идут результаты инструментов, служебные вставки клиента и сессии короче двух сообщений.

Сессии, запущенные из `/tmp` или `~/.cache`, пропускаются целиком: это стенды и пробные прогоны, а не работа. Список таких каталогов задаёт переменная `AGENT_EPHEMERAL_ROOTS`.

Секреты известных форматов (ключи облаков, токены GitHub и Slack, закрытые ключи) заменяются на `[СЕКРЕТ СКРЫТ]` теми же паттернами, что у секрет-гейта. Это страховка, а не гарантия: ключ в нестандартном формате останется в выгрузке. Время в выгрузке местное, в часовом поясе машины.

Длинный ответ агента обрезается на 12 000 знаков. Обрезка честно помечается в шапке полем `truncated: true`, а полный текст всегда остаётся в исходнике, путь к которому лежит в поле `raw_locator`.

Выгрузка это поисковый след, а не архив. Если нужно доказательство, открывается исходник по `raw_locator`, а продолжить сессию можно командой из поля `native_resume`.

## Настройка

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `AGENT_MEMORY_DIR` | корень выгрузок и состояния синхронизации | `~/agent-memory` |
| `QMD_BIN` | путь к `qmd`, если планировщик его не находит | ищется в PATH и типовых каталогах |
| `SYNC_EXPORTERS` | какие выгрузчики запускать | `cc,codex` |
| `AGENT_EPHEMERAL_ROOTS` | каталоги стендов через системный разделитель путей | `~/.cache`, `/tmp` и системный temp |

Лог синхронизации лежит в `~/agent-memory/.sync/sync.log`.

## Другой агент

Чтобы добавить агента, у которого история лежит в файлах, напиши выгрузчик по образцу `codex_history_to_md.py`: разобрать его формат, собрать реплики, записать шапку через `contract_lines()`. Добавь его в словари `EXPORTERS` в `sync.py` и `RESUME_COMMANDS` в `contract.py`, заведи коллекцию QMD и добавь тест в `tests/test_memory.py` на синтетической сессии.

## Проверка

```bash
python3 -m unittest discover tests      # из корня штаба, на синтетике
python3 memory/sync.py --status         # живое состояние на этой машине
```
